# Phase 4 人工测试文档

## 1. 用途与判定

适用：elfin Phase 4；依据 [开发报告](Phase-4-开发报告.md)、[执行规范](Windows桌面小精灵_V1_Codex执行规范.md)、[角色包 Schema](character-manifest.schema.json)。

本文件最初是待执行的验收清单。2026-08-30 已收到部分人工反馈，并完成代码、设置、日志及 Debug/Release 自动回归复核；仍缺少的视觉、交互、方向素材和真实多屏/DPI 结果不能由自动测试替代，Phase 4 保持 PARTIAL。

每项结果填写：**PASS / FAIL / BLOCKED / 未测**，并记录实际现象、证据或缺失条件。没有对应显示器、DPI 或角色素材时填写 BLOCKED，不能填写 PASS。

- 核心用例全部实际通过、自动回归通过，才可申请确认 Phase 4 PASS。
- 核心用例失败、阻塞或未执行：保持 PARTIAL，修复/补测后复核；无法启动或核心功能整体不可用可判 FAIL。
- 扩展环境尚未覆盖时保留环境风险，不得把“单屏通过”写成“Windows 10/11、多屏、混合 DPI 全通过”。
- 不测试 Phase 5+ 的正式页面、快捷键、办公、AI、TTS 或智能全屏穿透。

### 3.2 构建并建立独立便携副本

在 PowerShell 执行。下面仅提供操作命令，本次文档编写没有执行它们。

```powershell
Set-Location 'D:\workspace\elfin'
.\tools\Verify-Phase4.ps1 -Configuration Debug
```

确认 restore / build / test 全部成功后再执行以下命令。复制会排除原输出目录的 UserData，避免带入已有用户配置；不需要删除任何旧目录。

```powershell
$phase4Source = 'D:\workspace\elfin\src\DesktopPet.App\bin\Debug\net10.0-windows'
$phase4Run = Join-Path 'D:\workspace\elfin\artifacts' ('phase4-manual-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $phase4Run | Out-Null
Get-ChildItem -LiteralPath $phase4Source |
    Where-Object { $_.Name -ne 'UserData' } |
    Copy-Item -Destination $phase4Run -Recurse
$env:DOTNET_ROOT = 'D:\workspace\elfin\.tools\dotnet'
Write-Output $phase4Run
& (Join-Path $phase4Run 'DesktopPet.App.exe') --portable
```

记录输出的测试目录，后续重启始终启动**同一个目录中的 EXE，带 --portable**。测试数据为该目录的 `UserData/`；设置在 `UserData/config/settings.json`，日志在 `UserData/logs/`。不要给普通人工运行添加 `--smoke-test`，它会自动退出；`--data-root` 也不是普通启动参数。

Release 验证：先退出测试实例，执行 `Verify-Phase4.ps1 -Configuration Release`，把上面 source 路径中的 Debug 改为 Release，创建另一份独立副本；记录两套目录，不混用。

### 3.3 操作入口与观察规则

双击小精灵打开控制中心，向下滚动到“Phase 4 · 移动开发诊断”。四个下拉依次为：移动模式、允许显示器、运动风格、混合策略。修改后点击“应用移动设置”；“刷新”才更新移动诊断快照。

- 基础测试使用“当前显示器”；仅指定多屏用例才显式开放跨屏。
- 起始默认应为“混合 / 当前显示器 / 自然 / SmartHybrid”。
- 移动由行为调度器随机选择，应用设置不等于立即移动。普通观察建议 3–5 分钟；Hybrid 扩大范围建议 5–10 分钟。
- 连续至少观察两次完整移动；没有观察到时记录时长、模式、角色、可见性、诊断与日志，先判未测/BLOCKED 并排查，不能仅凭静止宣称移动通过或立刻判失败。
- 不反复点击小精灵或重新应用设置来“催动”：互动会影响空闲时长，重新配置会重启调度。
- Home 是画布锚点，Target 是窗口左上角，不能把两者直接当成同一种坐标比较。默认 220 DIP 画布、底部中点锚点；100% 缩放时 Home 对应的原点为 (Home.X−110, Home.Y−220)。
- 数学限速由自动测试验证；人工主要确认平滑、停止、边界与交互，不凭肉眼声称精确测得 300 DIP/s 上限。

### 3.4 测试角色

内置“开发测试 · 蓝团子”（Basic）只有静态 idle；“开发测试 · 橙团子”（Standard）有 idle/blink/happy/rest，**两者都没有 walk、左右专用动画或镜像声明**。它们能验证旧包 fallback，不能单独证明左右朝向正确。

朝向用例需额外准备副本：

1. 将 `tests/Fixtures/Characters/dev-basic` 完整复制到测试目录下的新包文件夹，不改仓库原件。
2. 每个副本用不同的 manifest.id，例如 `manual.phase4.directional` / `manual.phase4.mirror` / `manual.phase4.no-mirror` / `manual.phase4.generic`，并修改显示名便于识别。
3. 保留原有必填字段、idle、preview/fallback；minimumAppVersion 可设为 `0.4.0`，schemaVersion 仍为 1。
4. 自备两张方向明显且不对称的透明 PNG，分别放入 `images/left.png` 与 `images/right.png`。例如向左/向右箭头；不要用左右对称圆球判断镜像。
5. 按下表修改**副本**的 manifest；动画格式可使用 `{"type":"static","path":"images/right.png","loop":true}`。动画静态也可以验证移动语义。
6. 通过“选择文件夹…”→“校验”→“导入”→选择角色→“激活”。每个 ID 只安装一次；修改后重新测试需使用新的测试 ID，程序拒绝同 ID 覆盖。

| 副本          | animations 新增内容                               | supportsMirroring | 用途                         |
| ----------- | --------------------------------------------- | ----------------- | -------------------------- |
| Directional | walk-left 指向 left.png；walk-right 指向 right.png | true              | 专用方向优先，不错误镜像               |
| Mirror      | 仅 walk-right 指向 right.png                     | true              | 向左时镜像右向素材                  |
| NoMirror    | 仅 walk-right 指向 right.png                     | false             | 向左缺资源时 idle fallback，不强制镜像 |
| Generic     | 仅 walk 指向 right.png                           | false             | 普通 walk fallback，不假定朝向     |

可为一个副本添加 `"visualAnchor":{"x":0.4,"y":0.95}` 进行锚点测试。PNG/JSON/TXT 以外的额外文件不要打入包；不要把完整上述表格或不完整 JSON 片段当作整个 manifest。

如果缺少这些方向素材，A02–A05 标记 BLOCKED；不能用内置角色的 idle 代替方向验收。

## 6. 常见现象与失败分界

| 现象                    | 处理                                                |
| --------------------- | ------------------------------------------------- |
| 应用设置后没有立刻移动           | 正常可能；等待调度，确认非固定、可见、可交互、授权屏在线，记录诊断和等待时长。           |
| 移动日志有 Move，但视觉没有 walk | Basic/Standard 缺 walk 时预期 fallback；不能据此证明朝向正常。    |
| 开放所有显示器仍不跨屏           | 检查工作区连续性、窗口最大包络、随机目标及 45 秒段长限制；无实际跨越就不能填“跨屏成功”。   |
| 角色进入穿透后拖不动            | 先从托盘“恢复鼠标交互”；恢复入口失效属于失败，不靠反复重启掩盖。                 |
| 仅点击角色透明边缘可以穿过         | 不能证明穿透开关有效；必须点不透明实体部分复验。                          |
| 旧 Home 与新位置不同         | 自主移动不改 Home；手动拖动默认会改，updateHomeOnDrag=false 时不会改。 |
| JSON 编辑后恢复全部默认        | 检查格式/字段；这不是 H04 的有效坐标恢复证据。                        |

遇到窗口丢失先尝试托盘显示/恢复交互；仍失败则保存现场和测试目录，不删除配置、不改仓库、不强杀其他应用。结束测试后恢复屏幕设置并退出测试实例。
